Fase 1 · Vibe Coding

Crea la app con un solo prompt

Un prompt. Treinta segundos. App funcionando. Asi arranca el vibe coding: le dices que quieres y aparece. En Kiro eso es el agente Default, la conversacion libre.

Describe lo que quieres construir…
aDefault bAuto cAutopilot
  • aAgente. Default para chat libre. Spec, Quick Spec, Bug Fix y Plan para trabajo estructurado (los veras en la mision 3).
  • bModelo. Auto es el router de Kiro: elige el modelo por ti y es la base de creditos (1x). Puedes fijar uno, como Claude Sonnet u Opus; los mas potentes consumen mas creditos.
  • cAutopilot. Viene activado: Kiro trabaja de punta a punta. Apagalo (Supervised) si quieres aprobar cada edicion.
En Kiro Abre una sesion nueva. En la pantalla "Let's build" escribe directo: eso usa el agente Default.
Kiro Chat
Crea un juego tipo runner: el fantasma de Kiro corre, esquiva obstaculos saltando con la barra espaciadora y acumula puntaje. HTML, CSS y JS.

¿Algo salio mal? Cada prompt crea un checkpoint: elige "Restore" en el chat y Kiro vuelve atras el codigo y el contexto a ese punto.

Para ver la app: instala la extension Live Server (Cmd+Shift+X → buscar "Live Server"). Click derecho en index.html → "Open with Live Server". Alternativa: abre el archivo directo en el browser (Cmd+O).

Guia del presentador

"Un prompt. Treinta segundos. Tenemos un juego. Pero... ¿que pasa cuando otro dev toca este codigo?"

Es probable que Kiro cree carpetas, tests, package.json, etc. Dejalo — eso es justamente el problema que M2 (steering) viene a resolver. Si alguien pregunta, decir: "Exacto, eso es vibe coding sin reglas."

Mostrar la barra del chat: el selector de agentes (Default, Spec, Quick Spec, Bug Fix, Plan), el de modelos (Auto por defecto) y Autopilot. Hoy arrancamos con Default.

Para ver la app: Live Server (extension) o abrir index.html directo en el browser (Cmd+O / Ctrl+O).

Pregunta a la audiencia: "¿Quienes ya conocen Kiro? ¿Quienes usan otra herramienta tipo Cursor?"

~3 min

Fase 1 · Steering

Haz que Kiro siga TUS reglas

Sin convenciones, cada prompt produce codigo distinto. El steering es el "que quiero": reglas que Kiro lee automaticamente en cada interaccion.

Kiro Chat
Crea un steering file con las convenciones de nuestro proyecto:
- Proyecto simple: maximo 3 archivos (html, css, js). No crear carpetas src/, tests/, ni package.json
- No crear unit tests ni archivos de configuracion
- Mensajes de error en espanol
- camelCase para variables y funciones
- Comentarios JSDoc en todas las funciones
- try/catch en todo
- Separar html, css y js en archivos distintos
- Color principal #9147ff y #c59eff
- Tipografia Roboto

Ahora pruebalo:

Kiro Chat
Si no lo hiciste automaticamente, refactoriza el juego siguiendo las convenciones. Hazme un resumen de los cambios.

Cada steering define cuando se incluye: always (por defecto), fileMatch (segun el tipo de archivo), auto (cuando tu pedido coincide con su descripcion) o manual (lo llamas con #nombre en el chat). Kiro tambien lee AGENTS.md automaticamente.

Guia del presentador

"No le repeti las reglas. Las leyo solo. Para siempre, para todo el equipo."

Mostrar que el steering aparece en .kiro/steering/ y en el panel lateral. Destacar el contraste con M1: "¿Recuerdan las carpetas, los tests, el package.json? Ahora el steering dice 'maximo 3 archivos, sin tests'. Kiro lo reorganiza solo."

Pregunta: "¿Que convenciones pondrian ustedes? ¿Arquitectura? ¿Seguridad? ¿Patrones de diseno?"

~5 min

Mision 3 · Specs

Planifica antes de codear

El vibe coding es rapido pero impredecible. Un spec escribe el plan antes que el codigo.

sigue sigue
.kiro/specs/vidas-y-dificultad/requirements.md

# Requirements

## 1. Vidas

User story: Como jugador, quiero 3 vidas, para no perder al primer choque.

Acceptance criteria

  1. WHEN la partida empieza THE SYSTEM SHALL mostrar 3 vidas
  2. WHEN el fantasma choca con un obstaculo THE SYSTEM SHALL restar 1 vida
  3. WHEN las vidas llegan a 0 THE SYSTEM SHALL mostrar game over

Que debe hacer el juego, en criterios EARS que se pueden testear.

.kiro/specs/vidas-y-dificultad/design.md

# Design

## Arquitectura

Game loop→ Colisiones→ Vidas→ Game over Dificultad +velocidad / 100 pts localStorage highScore

## Modelo de datos

state = { lives: 3, score, speed, highScore }

## Manejo de errores · Testing

Si localStorage no esta disponible, el juego sigue sin guardar el record.

Como se construye. Todavia cero lineas de codigo.

.kiro/specs/vidas-y-dificultad/tasks.md

# Tasks

  • 1. Agregar estado de vidas al juego
    • 1.1 Iniciar con lives = 3
    • 1.2 Dibujar las vidas en pantalla
  • 2. Restar una vida al chocar
  • 3. Subir la velocidad cada 100 puntos
  • 4. Guardar el high score en localStorage
  • 5. Pantalla de game over con reiniciar
Run all Tasks

Pasos con checkbox. Run all Tasks los ejecuta en orden.

  1. Abajo en el chat, cambia el agente a Quick Spec.

    ¿Bug? Bug Fix ¿Feature clara? Quick Spec ¿Ambigua o critica? Spec ¿Sin documentos? Plan

    El selector dice Quick Spec.

  2. Pega el prompt y responde sus preguntas.

    Quick Spec
    Agrega un sistema de vidas y dificultad progresiva al juego. El jugador empieza con 3 vidas, pierde una al chocar, y la velocidad aumenta cada 100 puntos. Guardar el high score en localStorage. Mostrar pantalla de game over con opcion de reiniciar.

    Aparecen requirements.md, design.md y tasks.md en .kiro/specs/.

  3. En tasks.md, haz clic en Run all Tasks.

    Las tareas se marcan y el juego tiene vidas, high score y game over.

Tu feature es clara y la quieres rapido. ¿Que agente usas?

Mas detalles
  • Spec pausa para que apruebes cada documento. Elige Requirements-First si sabes el comportamiento o Design-First si ya tienes la arquitectura.
  • Bug Fix genera bugfix.md con el analisis de la causa.
  • Tambien puedes crear specs desde el panel Specs → +. kiro.dev/docs/specs
Si algo falla
  • ¿Falto algo? Edita requirements.md y en tasks.md usa Sync Files: crea las tareas que faltan.
Guia del presentador

"No es un prompt que espero que funcione. Es un plan escrito que puedo revisar antes de que exista una linea de codigo."

Usar el arbol de decision: esta feature es clara, por eso Quick Spec (mucho mas rapido que el Spec estandar, que pausa para aprobar cada fase). Abrir los 3 documentos: requirements con criterios EARS, design con arquitectura, tasks con checkboxes.

Recomendar no editar los archivos .md directamente sino por el chat, para mantener coherencia entre las 3 piezas.

Pregunta: "¿Cuantas lineas de codigo nueva hemos escrito? Cero. Estamos refinando."

~10 min (con el agente Spec y sus aprobaciones, 15-20)

Mision 4 · Hooks

El IDE que vigila por ti

Un hook es una regla automatica: cuando pasa algo, Kiro actua sin que se lo pidas.

Guardas ejemplo.jsCmd S
HookFile Save · *.js
Kiro avisa"sumar() no tiene JSDoc"
Otros eventos: File Create · Prompt Submit · Agent Stop · Pre Tool Use · Manual

  1. Panel Agent Hooks → + → "Ask Kiro to create a hook", y pega:

    Crear hook
    Cuando guarde un archivo JavaScript, revisa si hay errores o funciones sin documentacion JSDoc y avisame en el chat.

    Un hook nuevo en el panel, con evento File Save.

  2. Pruebalo con un archivo nuevo:

    Default
    Crea un archivo ejemplo.js con una funcion simple sin JSDoc y guardalo.

    Al guardarse, Kiro avisa en el chat que falta JSDoc.

Quieres buscar secretos cada vez que el agente termina. ¿Que evento usas?

Mas detalles
  • Eventos disponibles: File Save, File Create, File Delete, Prompt Submit, Agent Stop, Pre/Post Tool Use, Pre/Post Task Execution y Manual.
  • Pre Tool Use sirve para frenar una accion antes de que ocurra, por ejemplo un comando peligroso. kiro.dev/docs/hooks
Si algo falla
  • En el panel Agent Hooks, revisa que el hook este habilitado (icono del ojo).
  • Confirma que el evento sea File Save y que el patron incluya *.js.
Guia del presentador

"No corri ningun comando. El IDE reacciono solo."

Crear ejemplo.js en vivo (pedirlo en el chat con Cmd+L / Ctrl+L), guardar y mostrar como se dispara el hook. Repasar los eventos: File Save, File Create, File Delete, Prompt Submit, Agent Stop, Pre/Post Tool Use, Pre/Post Task Execution y Manual. No hay evento de git commit.

Pregunta: "¿Que hooks les serian utiles? ¿Buscar secretos cuando el agente termina (Agent Stop)? ¿Bloquear comandos peligrosos antes de que se ejecuten (Pre Tool Use)? ¿Revisar que el README este actualizado?"

Fase 2 · Agents

Tu senior dev personal

La IA generica puede tocar todo y aprueba cualquier cosa. Un custom agent es un especialista: define que herramientas y permisos tiene, y con que instrucciones trabaja.

Kiro Chat
Crea un custom agent llamado "revisor" que actue como un senior developer estricto. Solo puede leer archivos, no editarlos. Solo aprueba codigo con manejo de errores explicito y funciones documentadas con JSDoc.

Usalo:

Kiro Chat
Usa el agente revisor para revisar el codigo JavaScript del juego y dime si lo aprobarias para produccion.

Tambien puedes elegirlo en el selector de agentes (abajo en el chat, donde dice "Default"). Y Kiro puede lanzar varios como subagentes en paralelo (seguridad, UI, arquitectura) con una sola instruccion.

Guia del presentador

"Tiene el criterio de tu equipo y solo las herramientas que necesita. No es una IA generica, es TU senior dev."

Mostrar .kiro/agents/revisor.md: el frontmatter define name, description, tools y permissions; el cuerpo es su system prompt. Diferencia clave: el steering influye en como piensa Kiro; un agente ademas controla que herramientas puede usar.

Pregunta: "¿Que agentes crearian? ¿Seguridad? ¿Arquitectura? ¿Un agente que revise contra la documentacion de una API interna?"

~5 min

Fase 2 · Web Search

Busca sin salir del IDE

Necesitas un dato, sales al browser, abres 5 pestanas, pierdes el flow. Kiro busca en internet directo desde el chat.

Kiro Chat
¿Cuales son las mejores practicas para hacer un juego runner en el browser con buen game feel? Busca en internet.

Puedes ser intencional: "busca en internet" o "investiga en la documentacion oficial". Util para validar buenas practicas o datos actualizados.

Guia del presentador

"No abri ninguna pestana. El dato llego al chat."

Mostrar que la respuesta cita fuentes: Kiro uso su herramienta integrada web_search (y web_fetch para leer paginas). Util para documentacion, buenas practicas y datos que el modelo no tiene en su entrenamiento.

~2 min

Fase 2 · Workflows

Arma un equipo de agentes

Hay trabajo que no cabe en una sola sesion: investigar, implementar, revisar y corregir. Un workflow es un plan para un equipo de agentes: Kiro define los pasos y el orden, cada paso corre en su propia sesion con contexto limpio, y puede repetir o ir en paralelo.

Investigaweb search Implementasigue el steering Revisortu agente de la M5 Listo si rechaza, vuelve a implementar
En Kiro Workspace Configuration → Workflows → Enable (viene apagado)
Kiro Chat
Quiero agregar power-ups al juego (escudo e iman). Arma un workflow: un agente investiga en internet buenas practicas de power-ups en juegos runner, otro los implementa siguiendo el steering, y el agente revisor revisa el resultado. Si el revisor rechaza, vuelve a implementar.

Para tareas chicas quedate en el chat: los workflows son para trabajo que no cabe en una sesion. Las recetas reutilizables viven en .kiro/workflows/ (JSON o YAML) y Kiro trae tres de fabrica: investigate, feature-pipeline y publish-pr.

Guia del presentador

"No es un agente haciendo todo: es un equipo con un plan, y cada paso arranca con la cabeza limpia."

Mostrar el panel Workflows: seleccionar un paso para abrirlo en su pestana y, si pasa, mostrar el loop cuando el revisor rechaza. Contar que es nuevo (Kiro IDE 1.2, septiembre 2026) y opcional. Une todo lo anterior: web search en la investigacion, steering al implementar, el agente revisor al final.

Pregunta: "¿Que proceso de su equipo podria ser un workflow? ¿Investigar un incidente? ¿Feature, tests y PR?"

~7 min

Fase 3 · Skills

Dale expertise a Kiro

El steering dice "que quiero". La skill dice "como se hace algo especifico": conocimiento de dominio que Kiro activa cuando lo necesita.

Kiro Chat
Investiga en internet como se crean skills en Kiro. Luego crea una skill llamada "game-physics" que sepa sobre gravedad en juegos 2D, curvas de dificultad, hitboxes y game feel.

Pruebalo:

Kiro Chat
El salto del personaje se siente flotante. ¿Como hago que se sienta mas responsivo y satisfactorio?

No todo hay que escribirlo: Kiro usa el estandar abierto Agent Skills, el mismo de Claude Code. Importa una skill publicada por otros:

En Kiro Panel Agent Steering & Skills → + → "Import a skill" → GitHub → pega la URL de la carpeta de la skill (no la raiz del repo)
Anthropic · frontend-design Direccion estetica, tipografia y diseno que no se ve generico.
URL de la skill
https://github.com/anthropics/skills/tree/main/skills/frontend-design
AWS · launch-with-aws Lleva una app web hecha con vibe coding a AWS, del analisis al deploy.
URL de la skill
https://github.com/aws/agent-toolkit-for-aws/tree/main/skills/core-skills/launch-with-aws
Kiro Chat
Usa la skill frontend-design para redisenar la pantalla de inicio del juego, respetando los colores y la tipografia del steering.

Lee una skill antes de importarla: algunas traen scripts que Kiro puede ejecutar. Si la skill no aparece en el panel, pidele a Kiro que la revise contra la documentacion oficial (name debe coincidir con el nombre de la carpeta).

Guia del presentador

"Kiro supo cuando necesitaba ese conocimiento. No se lo tuve que decir."

Mostrar .kiro/skills/game-physics/SKILL.md: frontmatter con name y description; Kiro solo carga la description al inicio y el resto cuando tu pedido coincide (tambien se puede llamar a mano con /game-physics). Diferencia: steering = convenciones siempre presentes (el que), skills = conocimiento bajo demanda y portable (el como), agents = herramientas y permisos (el especialista).

Mostrar que la skill de Anthropic funciona tal cual: es el mismo formato SKILL.md que usa Claude Code.

Probar un salto en el juego para mostrar que ahora se siente mejor fisicamente.

Pregunta: "¿Que conocimiento de dominio tiene su negocio que podria ser una skill? ¿KPIs? ¿Modelos de datos? ¿APIs internas?"

~7 min

Fase 3 · MCP

Conecta con AWS en tiempo real

La IA generica no sabe que servicios existen hoy. Los MCP son conectores que le dan a Kiro acceso a fuentes de informacion externas en tiempo real.

Kiro Chat
Instala el MCP de AWS Documentation a nivel workspace. Crea el archivo .kiro/settings/mcp.json con esta configuracion:

{
  "mcpServers": {
    "awslabs.aws-documentation-mcp-server": {
      "command": "uvx",
      "args": ["awslabs.aws-documentation-mcp-server@latest"],
      "env": {
        "FASTMCP_LOG_LEVEL": "ERROR",
        "AWS_DOCUMENTATION_PARTITION": "aws"
      },
      "disabled": false,
      "autoApprove": []
    }
  }
}

Luego busca en la documentacion oficial cual es la mejor forma de hacer deploy de esta app a hosting estatico en AWS.

Workspace (.kiro/settings/mcp.json) vive en el proyecto y puedes versionarlo con el equipo. Global (~/.kiro/settings/mcp.json) queda solo en tu maquina. Si existen ambos, gana el de workspace. Atajo: en github.com/awslabs/mcp cada servidor tiene un boton "Add to Kiro". Mas info: awslabs/aws-documentation-mcp-server

¿Prefieres instalar manual? Copia este JSON en .kiro/settings/mcp.json
mcp.json
{
  "mcpServers": {
    "awslabs.aws-documentation-mcp-server": {
      "command": "uvx",
      "args": ["awslabs.aws-documentation-mcp-server@latest"],
      "env": {
        "FASTMCP_LOG_LEVEL": "ERROR",
        "AWS_DOCUMENTATION_PARTITION": "aws"
      },
      "disabled": false,
      "autoApprove": []
    }
  }
}

Este es solo un ejemplo. Hay cientos de MCPs: AWS publica mas de 60 (AWS MCP Server, IaC, Documentation...) y hay de GitHub, Atlassian, bases de datos, Figma, Slack y mas. Son conectores universales.

Guia del presentador

"Un clic en GitHub. Documentacion oficial, leida en tiempo real, aplicada a tu proyecto."

Abrir github.com/awslabs/mcp y mostrar el boton "Add to Kiro". Recomendar AWS Documentation como primer MCP. Mostrar la alternativa manual con el JSON para quienes prefieran copiar.

Si el servidor no arranca, lo mas comun es que falte uvx: pedirle a Kiro que instale uv.

Pregunta: "¿Los MCP son solo de AWS? No. Hay de Atlassian, GitHub, bases de datos... Son conectores universales."

~5 min

Fase 3 · Powers

Empaqueta todo en un clic

Todo funciona pero vive disperso en .kiro/. Un Power empaqueta skills, MCPs y steering en un paquete instalable, que Kiro activa solo cuando tu pedido lo necesita.

En Kiro Panel de Powers (fantasma con rayo) → busca "Power Builder" → Install
Kiro Chat
Quiero crear un Power que empaquete lo que hicimos: el steering de convenciones, la skill de game physics y el MCP de AWS Documentation. Usa el Power Builder con el formato Agent Plugins.

Los hooks y los custom agents no viajan en un Power: se comparten versionando .kiro/ en el repo del proyecto.

Prueba instalando este Power que creamos en el workshop: kiro-game-dev-toolkit. Documentacion: kiro.dev/docs/powers/installation

Guia del presentador

"Con MCP conectaste la IA a una herramienta. Con Powers le diste el manual completo."

Instalar el Power Builder primero. Mostrar la estructura que genera: plugin.json (nombre, version, keywords que lo activan), skills/ y mcp.json. Los Powers viejos con POWER.md siguen funcionando. Explicar que esto se sube a un repo y cualquiera lo instala.

Si hay tiempo: crear una carpeta nueva, instalar el power desde URL y mostrar como la experiencia cambia completamente.

Pregunta: "¿Que powers crearian para su equipo? ¿Uno de seguridad? ¿De arquitectura? ¿De onboarding para devs nuevos?"
